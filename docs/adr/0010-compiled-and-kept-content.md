# One Committed Map Package per Mission, with Compiled and Kept Content

Every Mission keeps its **Map Package** committed in the Workspace, beside its **Mission Blueprint**, and compiles write into that package in place. Each part of the package is either **Compiled Content**, which the Blueprint owns and every compile rewrites, or **Kept Content**, which the package owns and which is edited where it lies, by the author in the Editor or by the assistant with tools that change only what they touch. A compile record beside the Blueprint lists everything the last compile wrote: object ids, regions, triggers and their Galaxy, catalog entries, string keys, files and terrain cells. The next compile replaces exactly what the record lists, and anything not on it is Kept Content. A part may stay Kept Content for good. It becomes Compiled Content only when a change calls for the Blueprint, such as rebuilding a scene as a Cinematic or regenerating an area from Zones.

This is how a hand-made map joins a Workspace (**Import**: copy the package in and start with everything Kept), and it is also how Editor polish on a compiled Mission survives the next compile. It replaces the unbuilt "layer locking" of [ADR-0001](./0001-round-trip-unpacked-map-packages.md).

## Considered Options

- **Two kinds of Mission**, compiled ones whose package is a git-ignored build product and imported ones whose package is the source. Rejected: every tool would need both paths, and Editor polish on a compiled Mission would still be lost.
- **Convert an imported map wholly into a Blueprint.** About half of the first imported map, a hand-made city mission, converts as it stands (units, points, cameras, regions, doodads, its conversation). The rest doesn't: its hand-sculpted and painted terrain, its map-local game data, 41 GUI triggers calling 39 functions the trigger catalog lacks, and six hand-keyframed cutscenes would become opaque data in the Blueprint, or be rebuilt and lose their polish.
- **Recompute ownership from the Blueprint** (a stable object id it would produce means the object is ours). Rejected: an Anchor deleted from the Blueprint would leave its object behind as if it were Kept, and terrain cells and catalog entries have no such id.
- **Markers in the package** (a trigger category, name prefixes). Rejected: they show in the Editor, break when the author moves or renames things, and can't mark terrain cells or data entries.

## Consequences

- **The Editor and the compiler share files.** When the author has changed Compiled Content in the Editor, what `sync` can bring back goes into the Blueprint as before. For anything else (a hand-fixed generated cliff, an edited compiled trigger), the compile stops and the author decides part by part: keep it, which makes it Kept Content and drops it from the record, or discard it. A save that only re-lays out what the compile wrote (the Editor's attribute order, dropped defaults, its `HeightAbsolute` flag, heights quantized again) isn't a change: objects and a generating Zone's heights are compared by what they say, within sync's tolerances (#601, #602).
- **sync adopts what the author places on Compiled ground** (#603). In the Mission's own package, a doodad the author placed on ground the compile writes (a generating Zone's, or any Zone's on a generated map) becomes a doodad Anchor that keeps the Editor's Id (`editorId`), and the compile takes the object over where it stands. Kept doodads already standing there are adopted the same way, the author's call (2026-11-10). One whose type the catalog lacks stays Kept, with a note. Units, points and cameras the author places stay Kept, since a Kept trigger may name them. Beside Kept ground, objects and regions sync only from the Mission's own package with its record, compared with the ground and dressing the compile writes there.
- **`MapScript.galaxy` is spliced, not generated.** Test Document runs the script as it stands, and only an Editor save rebuilds it from `Triggers` ([editor-and-engine.md](../reference/editor-and-engine.md#test-document-and-mapscriptgalaxy)). So a compile keeps the Editor's Galaxy for Kept triggers and inserts or replaces only its own blocks. A Kept trigger is tuned in its XML and its Galaxy together, only where the trigger catalog knows every function it calls; otherwise the author saves in the Editor. Splicing may prove brittle, so a test compares a spliced script with the one the Editor writes on save.
- **The Blueprint names what it builds on.** Compiled Content uses Kept Content only through a declared **Kept Reference**, found by Editor Id, and the checker fails when the package no longer has it.
- **Terrain is owned per Zone.** A Zone either generates its ground (Compiled cells) or is drawn over Kept ground as an area only. A generating Zone matches the Kept cliff level where a Connection crosses into Kept ground, and blends height at the seam.
- **Checks cover Kept Content.** A broken link (a line id, conversation, Kept Reference or asset that's gone) fails `pnpm check` wherever it is. A craft finding on Kept Content is a warning, since that content predates the rules.
- **Map-local game data is Kept Content**, edited in place. Data several Missions share goes to the Campaign Mod. Data belonging to a Mechanic stays with its Plugin.
- **A Kept conversation converts to its Screenplay.** `convert-screenplay` pairs an imported map's own conversation (`screenplay.script.conversationId`) with the pulled Screenplay by line id and records what the lines keep in `screenplay.script.conversion`. From then on the compile writes the conversation, its CSounds and its strings by entry, as a mod's conversion does, and the first compile runs under the Equivalence Check against the Mission Blueprint's `acceptedDifferences`. Unlike a mod's, a line keeps its imported Sound only while its words are the recording's. A line whose words changed plays the naming template's Sound and a placeholder voice, so an old recording of other words never plays, and the compile relinks a Kept cutscene's `soundLink` to it. A Sound the conversation no longer plays (a dropped line's, or a changed line's old one) goes with its CSound and its recording, and a dropped line's string goes too, unless a Kept trigger names the Sound. A Kept cutscene that still plays a dropped line fails the check. An unconverted conversation stays the package's own, and the compile says so.
- **The Blueprint no longer needs Zones or Beats** when its Map Package has Kept terrain. They are added when a job needs them.
- **Generated diffs.** Compiled files show up in the Workspace's git diffs. Generated placeholder audio stays git-ignored.

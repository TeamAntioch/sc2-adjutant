# Data rules for Mod Blueprint entries

`compile-mod` warns about these in a Mod Blueprint's Generic Entries (`packages/core/src/mods/data-rules.ts`, issue #740). Each warning names its fix. All five are **warnings, not refusals**: the stock data backs what it can. Three were checked in the Editor on 2026-11-21 (the table says what each showed), one test each on a map's data; the ability set id is not, and the level-1 question was settled in game (see the veterancy row). A hard check would need more than one test, so they stay warnings. The ideas came from comparing another project's notes (see `related-repos.md`); nothing of its code or text is used.

Evidence is from Blizzard's own catalogs (`core.sc2mod` and the other stock mods, from the game install or the public game-data mirror [sc2-arcade-watcher/sc2-game-data](https://github.com/sc2-arcade-watcher/sc2-game-data)) and the Editor's own strings, read 2026-11-18.

| Rule | Warning when | Evidence | Needs an Editor check |
|---|---|---|---|
| Per-level arrays start at `index="0"` | an entry with a `parent` writes `VeterancyLevelArray`, `LevelScalingArray` or `LevelUpgradeArray` and the first item has no `index` | The Editor names these fields' index "Level" (`EDSTR_FIELDINDEX_*`). Stock writes an unindexed first item in a base entry, where it is index 0. | Checked 2026-11-21 (the author, Data Editor, Behaviors): it **does not replace** level 0. A child with no `index` on its first item, over a parent with levels 0 and 1, showed 100, 200 and 999 at levels 0, 1 and 2: the item was added after the parent's. So the warning is right to ask for `index="0"`. One test, on a map's data, not a mod's. |
| A copied ability needs its own `AbilSetId` | an `Abil` entry with a `parent` sets no `AbilSetId` and either its class's stock default has one, or its Blueprint parent sets one | Stock `AbilData.xml` sets `AbilSetId` on the class defaults of `CAbilAttack` ("Attack"), `CAbilHarvest` ("Harv"), `CAbilRally` ("Rall") and `CAbilStop` ("Stop"). The Editor's hint for the field: abilities of the same type with the same id make a command to one apply to the others in the selection. A copy inherits it. | Whether sharing is ever wanted: the warning is advice, not an error. |
| `VeterancyLevelArray` index 0 is level 1; `VeterancySearchRadius` defaults to 10 | (no check) | The default is confirmed: `CGame` in stock `GameData.xml` writes `<VeterancySearchRadius value="10"/>`. Index 0 as level 1: starcoop's Mengsk ranks write an empty first item with `RankNameSchema` "...Rank0", so level 1 might have been index 0 or the item after it. | Checked in game 2026-11-22 (the author, Test Document, Editor version not recorded): a `CBehaviorVeterancy` with index 0 at 100 XP and index 1 at 200 XP, six invulnerable Zealots given 0, 100, 199, 200, 250 XP, and 150 then 100 more; `UnitXPGetCurrentLevel` read **0, 1, 1, 1, 1, 1**. So crossing index 0's threshold makes level 1: **index 0 is level 1**. Not understood: 200 and 250 XP read level 1, not 2, though index 1 is at 200. Untried: whether the unit needed something more for level 2 (a level cap, a rank name). One map's data, not a mod's. Left out of the checks: the level-1 reading is settled, the level-2 one is not. |
| An actor's parent is the same actor class | an `Actor` entry's `parent` is a Blueprint entry of another class that isn't a name-prefix base of the entry's class | Of 230 stock actor parent links, 215 are the same class. The other 15 are a subclass on its base (`CActorRegionQuad` on `CActorRegion`) or `CActorEditorPoint` on `CActorModel`, so "same class" is the safe choice, not the only valid one. Only parents inside the Blueprint are checked: the stock actors aren't in a reader here. | Checked 2026-11-21 (the author, Data Editor, Actors): it **does not refuse** one. A `CActorUnit` with a `CActorModel` parent loaded with its parent shown and no error. What the child inherits from a different class, and how it behaves in the game, was not looked at. The warning stays advice. |
| A named `CWeapon` is refused; use `CWeaponLegacy` | a `Weapon` entry of class `CWeapon` with an id | In the stock mods, 3,043 named weapons are `CWeaponLegacy`, 25 `CWeaponStrafe`, and none is a named `CWeapon` (it appears only as `default="1"`). | Checked 2026-11-21 (the author, Data Editor, Weapons): the Editor **dropped** it. A named `CWeapon` was not in the list while a named `CWeaponLegacy` beside it was. It is not shown as refused with a message: the Editor's log folder could not be read, so whether it logged anything is unknown. The warning's advice stands. |

A Mod's entries are checked on compile, after the schema check; `check-workspace` doesn't run them.

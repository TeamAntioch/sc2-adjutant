# Editor rules for Triggers and Galaxy

Seven rules about how the Editor reads and writes a `Triggers` file and its Galaxy came to us as unverified claims, from [VoVanRusLvSC2/SC2Editor-MCP-Codex](https://github.com/VoVanRusLvSC2/SC2Editor-MCP-Codex) (commit `4b230ed`, via the comparison in issue #735). We re-implemented nothing from that repo; each rule below was checked against our writers and against Editor-saved files already on disk. `packages/core/tests/triggers/editor-trigger-rules.test.ts` holds one test group per rule.

**Where the evidence is.** The Editor-saved reference is Blizzard's Nova campaign mod (`novacampaign.sc2mod`: its `Triggers`, `LibNovC.galaxy`, `LibNCUI_h.galaxy`), one of Blizzard's stock mods (`mods/missionpacks/`, from the game install or the public game-data mirror [sc2-arcade-watcher/sc2-game-data](https://github.com/sc2-arcade-watcher/sc2-game-data)). It is Editor-saved, not run through our Editor, and none of it was loaded in the Editor for this check. A rule only a live load can decide is marked **needs an Editor check**.

| Rule | Outcome | Why |
|---|---|---|
| Code on the `<ScriptCode>` tag line loads as empty | Confirmed in the Editor 2026-11-22: it loads empty. Covered by our writers | Every `<ScriptCode>` we write (`scriptCodeLines` in `library-xml.ts`, `custom-script.ts`) is a block: the tag alone on its line, the text indented below, the closing tag alone. The reader dedents it back. The Editor-saved files lay it out the same way. The Editor check (below) showed the tag-line form loads empty, so never writing it is right. |
| A literal-zero array bound collapses to a scalar | Doesn't arise: no save has a zero size, and the reader refuses one | The Editor holds an array's size inside `<VariableType>`, after `<Type>` and what it names, one `<ArraySize>` per dimension counted from `Dim="0"`: a literal (`<ArraySize Dim="0" Value="9"/>`) or a constant variable (`<ArraySize Dim="0" Type="Variable" Library=".." Id=".."/>`). The Nova, Swarm Story Util and thanson01 saves hold both, and no size of 0, so what the Editor writes for one isn't known: the reader refuses it, and the function stays Kept. Galaxy declares one more than each size: `string[10] lv_arcMissions` for 9 (Nova's `NC_DebugProgressCompleteToMission`), `string[libNCUI_gv_nUC_MissionRewardsMaxCount + 1] lv_techItemRewards` for a constant's (`NU_MissionSetRewards`), `int[7] gv_unloadAmount` for 6 (thanson01). We read and write array variables of any dimension, in a library function's and a structure's XML and in Galaxy for a library function's or a Kept trigger's locals (#944). See "Arrays and indexed values" below. |
| Library functions are emitted before map globals | Not applicable | A mod library's globals live in its `_h.galaxy` header, which its `.galaxy` includes first (`include "LibNovC_h"`); we splice only functions into `Lib<id>.galaxy`. The map script, which we write whole, goes libraries, globals, `InitGlobals`, then trigger functions, as tested. |
| A string initial value of `"0"`, `"false"` or `"null"` is dropped | Not applicable | The leave-out test compares rendered text with Galaxy's unquoted defaults (`GALAXY_DEFAULTS`, and `ZERO` for int, fixed and bool in the library renderer). A string renders quoted, so `"0"` is kept; tested for a library function's local. The map script has no string variables. |
| An implicit `trigger t` is not prepended in function bodies | Not applicable | The Editor writes a trigger parameter as a declared parameter like any other (`libNCUI_gf_NU_UpgradesClosed (trigger t)`, `t` being the parameter's own name). Nothing is implicit; we write exactly the parameters a function declares, and a trigger's own function has the fixed `(bool testConds, bool runActions)` signature. |
| Named-library references need an explicit `Library` | Covered | In a library's `Triggers` every reference, to the library's own elements too, carries `Library` (`refLine`). In a map's `Triggers` the game's elements name `Library="Ntve"` and the map's own carry none, as the Editor saves a map. Both tested. |
| `<Constant/>` goes inside `<VariableType>`; an initial value is `<Value Type="Param"/>` | Confirmed, and written | The Nova `Triggers` shows `<VariableType><Type Value="int"/><Constant/></VariableType>` and `<Value Type="Param" Library=".." Id=".."/>`; `<Constant/>` follows `<Type>` and what it names (`<GameType>`). Our variables write the type inside `<VariableType>` and the initial value as a `Param` reference (tested), and a constant's `<Constant/>` after its type, read back the same (#944). A constant is what an array's size names. In Galaxy a constant local is declared with its value and set nowhere else: `const string lv_tempConvoBankName = "PSTempConvoBank";` under Variable Declarations (Nova's `NS_TempConversationBank`), the same in a Kept trigger. No save has a constant array; the reader refuses one. |

## Editor check

**`<ScriptCode>` on the tag line, 2026-11-22 (Editor version not recorded).** A throwaway copy of a generated map had two custom scripts in `Triggers`, ids `5C0A1B0C` and `5C0A1B0D`: one in our block layout (the tag alone on its line, the code indented below, the closing tag alone), one with the whole script on the `<ScriptCode>` line. The author opened it in the Editor's Triggers module:

- **Block form:** the code showed, dedented, with its init function (`BlockInit`) in the "Initialization Function" box.
- **Tag-line form:** the code box was **empty**; the init function (`TagInit`) still showed. So the rule holds: code on the tag line loads as empty.
- **Ids:** a first try with ids that were not 8-digit hex (`ScriptBlock`, `ScriptTagLine`) showed neither script in the list. A custom script needs a hex id like the Editor's own.
- **Names:** the Editor listed each script under a name it made up (a run of random letters), since our element carries no name.
- **Unsaved marker:** the title gained a `*` as soon as the author clicked a script, with no edit. Viewing a custom script marks the document unsaved, which matters to the same-file refresh: it will refuse until the author closes without saving.

One small map, one Editor version (not recorded), one machine. The save-back (what the Editor writes for the tag-line script when it saves) was not tried.

No writer needed a change for these rules but the last two, arrays and constants, which the writers now write (#944).

## Where a Mission's generated triggers go

A Mission compile files each trigger and global variable it generates in a **Trigger Folder** (an Editor Category), from the Blueprint thing that made it (#816). You never name a folder. `build-mission-triggers.ts` holds the rules.

```
Mission                Tech, Mission Start, the outcomes (and a Trigger Scene played on the
                       victory outcome), hero deaths, Clocks; transitions and UI actions cued on no Beat
<Beat title>           one per Beat, in Beat order: Beat - <title>, its Lines, its Arms,
                       and transitions and UI actions cued on its start (or with its beatId)
  Objectives           what completes an Objective whose beatId is this Beat
  Encounters/<title>   an Encounter whose fromBeat is this Beat (the first Beat if it has none):
                       its start, Death, Ends, Timer, Damage, Behavior
  Waves/<title>        a Wave whose startsAtBeat is this Beat, though it runs on into later ones
Screenplay
  Scene <n>            a scene's Script Scene triggers (Played, After, Behind, Dropped),
                       its Trigger Scene and its Cinematic
  Cues                 Cue triggers, After <Kept trigger> hooks, and a condition only a cue reacts to
Mechanics/<title>      a Mechanic's triggers, whatever Plugin supplies them
Enemy AI               Enemy AI Start, Money
```

- **Names.** A Beat's folder is its `title`. A Wave's, Encounter's or Mechanic's is its optional `title`, or else its id in words: each `_` or `-` a space and each word upper case first, so `raid_quake` is "Raid Quake" (#903). Folder ids still come from paths by id, so a new title renames the folder where it is.
- **Variables.** Each folder's variables are in a `Variables` subfolder at its top. A variable that only one folder's triggers use goes in that folder's (a Wave's own state in `Waves/<title>`). One that triggers in more than one folder use, or that no trigger uses, goes in `Mission/Variables`. That includes a folder and its subfolder: a Wave's flag that its Beat's trigger also sets is Mission's.
- **Icons.** Each folder carries a Native Label: Mission Campaign, a Beat Story, Objectives Objective, Encounters Unit Group, Waves AI Advanced, Screenplay Transmission, Cues Event, Mechanics Game, Enemy AI AI, every Variables folder Variable. A Scene is Cutscene when it has a Trigger Scene or Cinematic, Conversation when it has lines only.
- **Empty folders** aren't written. A scene whose lines play straight from their cue's trigger files nothing of its own, so it has no folder.
- **Order.** The Editor writes MapScript's trigger sections depth first through the tree, so the compile does too, and a re-save in the Editor doesn't reorder it. Triggers of one folder keep the compile's order (Tech before Mission Start).
- **Your own filing wins.** A trigger you move into a folder of your own stays there, and a trigger you add by hand in a generated folder is kept there on the next compile (`splice-triggers.ts`). Folder ids come from their paths, so a recompile keeps the tree. Trigger names don't change with their folder.

### A Blueprint's own triggers

A Mission Blueprint's own trigger elements (ADR-0026) aren't filed by the rules above. Each is a JSON file in `missions/<id>/triggers/` that the Blueprint's `triggers` lists, a GUI Body with the trigger's name, `identifier`, `label`, `section`, `disabled` and `initiallyOff`, and its `variables`, `events`, `conditions` and `actions` (`src/domain/blueprint-trigger.ts`). Its globals are the Blueprint's `triggerVariables`, and its folders the Blueprint's `triggerFolders`, each filing `trigger:<id>`, `variable:<id>` and `category:<id>` items. A file may also hold a function, a comment, a preset type (`"kind": "preset"`, its values in order with any comment filed among them), a record (`"kind": "record"`, the Editor's Structure, filed as `structure:<id>`, its members as variables) or custom script (`"kind": "custom-script"`, its Galaxy as data and its `initFunction`). What no folder files goes in Root before the compile's own items: folders first, then custom script, preset types, records, globals, functions, triggers and comments. A preset type's Galaxy is a constant for each value (`const int ge_<preset>_<value> = <n>;`, numbered from 0) in Global Preset Declarations, before Global Variables, with an empty Global Presets after Trigger Variables, as the Editor writes it beside any preset type; only an integer preset type (`<PresetInteger/>`, base type int) whose values have none of their own is written, the one form every map save in the corpus has. A record's is its struct (`struct gs_<name> {`, each member declared as a local is, `};`) in Global Structures, after Constants. Custom script's block is a ruled `// Custom Script: <name>` heading and its script as it stands, in the Custom Script section, which ends with InitCustomScript calling each init function, and InitMap calls InitCustomScript after InitGlobals. Each section is made when the script has none, and taken out once nothing is left in it (`splice-map-script.ts`). Beside Kept triggers each stays where the package has it from one compile to the next (the splice writes it in place), where the compile's own go to the end each time. A library's element is `<library>/<id>`; the map's own (a Kept function or global, or the Blueprint's) is its Id alone. A dependency mod's global, and a member of one of its structures, is a library's element too (`"variable": "Cmpn/E5539606"`, `"member": { "variable": "Cmpn/C8F0D280" }`), written as the Editor writes it (`<Variable Type="Variable" Library="Cmpn" Id="E5539606"/>`) and named in Galaxy as the library names it (`libCmpn_gv_heroUnit.lv_artanis`); it is checked against the globals and structure members of the library in reach, read from the mod's package Triggers and its Blueprint interface's structures (`library-reach.ts`). The game's library data holds no globals, and no corpus map names a library's trigger. The compile writes the elements in the order the Editor reaches them, and their Galaxy through the Kept renderer (`src/triggers/blueprint-triggers.ts`), checked against `editor-triggers/authored-trigger`, cut from zspace01. It refuses, naming the element and its file, an Id a Kept element or the compile's own has, a Galaxy name (gt_, gv_) another trigger or global has, and a reference out of reach. A reference to an element a concept compiles to (a trigger, global or function of the compile's own) is refused pointing to the cues: hold the trigger until the cue, or start a Beat on its run. A Beat starts on, a cue waits on, and a hold holds a Blueprint trigger through a trigger reference in `kept` naming it by element Id, as for a Kept trigger (ADR-0026, #1036). Such a reference names nothing in the package, so a Mission whose Kept References all name its own triggers compiles into a new package with no compile record. The example Campaign's Ashfall Relay does this: its *Start Ash Tremors* is held in its body until the Crossing Beat starts. The walkthrough is in `packages/core/examples/example-campaign/README.md` (#1037).

A Kept trigger converts into the Blueprint with `convert_triggers` given a Mission (`src/map/convert-mission-triggers.ts`, #1030): it is read back into a GUI Body by the library reader in a map's form (`readMapTrigger`, its own references bare), keeping its element Ids, its name and its locals', and its text values' words (`Param/Value/<id>` and `Param/Expression/<id>`, by GameStrings file); custom script, in a call (Custom Script, `Ntve/00000123`) or a value (`<CustomType>` and `<ScriptCode>`), stays as data. It converts only when its XML comes back as the Editor's, its Galaxy as the Editor's section, and what it names is in reach; else it stays Kept, with why (`it calls VCMI/3F2DAB19 (and 10 more of its parts), which is out of reach: the library VCMI isn't in reach of the map …`). A call a hold switched off (ADR-0014) reads back on, as the Editor saved it before the hold. The compile then writes it in place of the Kept one under the Equivalence Check, its Triggers XML (`trigger:<id>`) and its three Galaxy blocks (`galaxy:MapScript.galaxy:trigger:gt_<name>` and its declaration and _Init call) compared with the Editor's, and the files come out byte for byte as they were. Checked against `editor-triggers/authored-trigger` (zspace01, calling Kept map functions), `custom-script` (thorner03, a Custom Script action), `transmission` (a current Editor save, half converted: the Kept Mission Start runs the converted Objective by its Id; Opening Transmission, which calls VoidCampaignMissionLib, is refused until #951) and `library-globals` (a current Editor save of a Mission: Initialization sets a member of its Campaign Mod's global, Cleanup reads one; a global out of reach, or one its library doesn't hold, is refused naming it and its library). Functions, globals, comments, folders, preset types, records and custom script convert the same way (#1032), each checked against a cut: `map-functions`, `globals-comments` and `folders` (thanson01), `presets` (thanson01's PRESET_MissionPhase, a comment among its values, and a global of it), `records` (pulnar02's two records, one with a member of the map's preset type) and `custom-script-element` (a custom script in a current Mission save's form). A global of the map's own preset type is `int` in Galaxy, its initial value the value's constant; a global of a record type stays Kept, since the Editor initializes each of its members in InitGlobals, with loops for array members, which the compile doesn't write yet.

### Writing a trigger in the Editor's terms

`write_blueprint_trigger` (#1033, `src/triggers/author-trigger.ts`, its I/O in `src/map/write-blueprint-trigger.ts`) writes a Blueprint trigger from a tree of calls by the Editor's names, or rewrites the Blueprint trigger of that name. It is the form an outline reads back to (#1034):

```jsonc
{
  "name": "Ping",
  "initiallyOff": true,
  "variables": [{ "name": "Targets", "type": "Unit Group", "value": { "function": "Empty Unit Group" } }],
  "events": [{ "function": "Periodic Event", "params": { "Duration": 2.5 } }],          // Time Type: its default, Game Time
  "conditions": [{ "function": "Comparison", "params": { "Value 1": { "function": "Unit In Unit Group", "params": { "Unit Group": { "variable": "Targets" } } }, "Operator": "==", "Value 2": true } }],
  "actions": [
    { "function": "MinimapPing", "params": { "Position": { "function": "Point", "params": { "X": 10, "Y": 20 } } } },
    { "function": "Text Message", "params": { "Message": "Ping!" } },                 // a text's words, in GameStrings
    { "function": "If Then Else", "blocks": { "If": [ … ], "Then": [ … ], "Else": [ … ] } },
    { "comment": "…" },
    { "customScript": "UISetCursorVisible(PlayerGroupAll(), true);" }                 // only where asked for
  ]
}
```

- **Functions** by name, identifier or `<library>/<id>`, resolved with `resolveFunction` against the libraries in reach (`missionLibraries`), and the map's Kept functions by their names in TriggerStrings (their interfaces read in map form, `readMapFunction`). A function's kind must fit where it stands: an event in `events`, a condition in `conditions` and an If's slot, an action elsewhere, one giving a value as a value. Where two functions share a name, the one whose kind fits is it (Built-In's Unit Is Selected is an event and a function); else the name is refused as ambiguous, naming each with its library, category and Id, until `library` is given (`map` for the map's own) or, within one library, its `<library>/<id>` (Built-In's two Nots both give a value).
- **Parameters** by name, or by reference (`Ntve/00000219`) where two of a function's share a name. One left out takes its default, the value a new call gets in the Editor (`params[<id>].default` in the library data), copied with Ids of its own, as the Editor writes every parameter of a call; a text in it takes its words from the library's GameStrings (`defaultTexts`; a Kept function's from the map's), `""` for an empty one (Create Objective's Description writes `StringToText("")`, Display Boss Bar's Title the words "Boss"). One with no default, or a text default whose words aren't in reach, must be given. `null` leaves a parameter unset, as the Editor saves a call not filled in; only in a disabled statement or trigger, which has no Galaxy. A parameter its template repeats (`#PARAM(<identifier>,<separator>)`, Combine Text Multiple's Text) takes a list, one Param per value.
- **Values** are checked against their parameter's type, each named as the Editor names it (`takes a Real, but Triggering Unit's value is a Unit`). A string is read by the type: a preset value by name (Game Time, `==`, a type's own presets such as Any Unit for a Unit, and the map's own preset values), a text's words, a String or an actor message, a trigger by name, a game link's id. An Integer fits where a Real is taken, as Galaxy takes it and the Editor saves it (Arithmetic (Integer) given to Point With Polar Offset's Angle in pkorhal02). Same As takes the type of the value its parameter was given (a default of another type must then be given: Comparison's Value 2 is Integer 1), Any Variable only a variable. A preset value given by its reference may be of another preset type of the same base, as an older Editor saved some (thanson01's Player Property (Get) value given to Modify Player Property's (Set)).
- **The other value forms** (#1061), each written as the Editor saves it:
  - `{ "preset": "GasOff" }`: a preset value by name, a library's (or as `<library>/<id>`) or the map's own (Kept preset types, by their names in TriggerStrings, or by Id).
  - `{ "bits": ["Ignore Placement"], "preset"?: … }`: a set of bits (`<ValuePreset>`s with the parameter's preset type), its values by name, none for none set; `preset` names the bits preset type where the parameter takes any. An older Editor's set naming no preset type is written with the parameter's.
  - `{ "expression": "~A~*2+~B~", "type": "Integer", "slots": { "B": 1, "A": … } }`: an Arithmetic or Expression value of type Integer, Real, String or Text, its slots in the order given (the Editor's). Every `~code~` its text names needs a slot, and every slot must be named in the text, but in a Text one, whose words may name only some. A Text expression's text is its words, written to GameStrings as `Param/Expression/<id>`.
  - `{ "value"?, "type", "gameType"?, "valueId"?, "typeInfo"?, "context"? }`: a literal, with what else the Editor saves of it: a placed unit's, point's, region's or camera's number and a player colour's or an ability command's index (`valueId`), an ability command's targeting (`typeInfo`), a user type instance's type (`context`).
  - Events may hold comments; a trigger may carry its `label`, a local its `identifier`; a block's slots are written in the order given (a save may hold Then before If).
- **Variables** are the trigger's locals, then Blueprint and Kept globals, by name or Id, then a library's globals by name (`{ "variable": "Hero Unit", "library"?: "Cmpn" }`, `library` only where two libraries' share it) or as `<library>/<id>`. A member is named by its name among the members of the structure its variable holds (`"member": { "variable": "Artanis" }`), a library's or the map's own (a Kept record), or by reference. The game's own libraries' globals aren't in the data (none of the corpus's triggers names one).
- **Ids.** Every new Id is 8 hex digits no element of the package, the compile record or the Blueprint has. A trigger is rewritten when the Blueprint has one of its name, or, to rename it, of its `id`. Rewriting keeps the trigger's Id and file, its other locales' words for what it keeps, each local's Id by its name, and every statement alike one it had in the same list (Ids aside, a text's words compared) with all its Ids. A call changed in place, the same function where one was, keeps its own Id and its unchanged parameters'.
- **Checks before writing.** What it names is checked as the compile checks it (`blueprintReferenceProblems`), and its Galaxy rendered by the Kept renderer among the Kept and Blueprint elements, so what is written compiles. A refusal lists every problem by place (`action 2 (Wait): Wait has no parameter "Length": its parameters are "Time", "Time Type"`), and nothing is written.
- **Custom script** is written only where the input asks for it. A function nothing in reach is named is refused pointing to `search_trigger_functions`, to custom script asked for, and to a Missing-Feature Report (the `report-missing-feature` skill).

Checked by `tests/map/write-blueprint-trigger.test.ts`: authored-trigger's trigger (zspace01), written in the Editor's terms, compiles to the Editor's section byte for byte; a periodic trigger calling Ping Minimap (outside core's catalog) with its defaults, a Text Message and custom script compiles to `TriggerAddEventTimePeriodic(gt_Ping, 2.5, c_timeGame);`, `MinimapPing(PlayerGroupAll(), Point(10.0, 20.0), 2.0, Color(100.00, 0.00, 0.00));` and its words in GameStrings. `tests/triggers/authoring-forms.test.ts` checks the other forms against cuts of Editor saves (`authoring-forms/`, from Heart of the Swarm's zhybrid01 and Legacy of the Void's pkorhal02, `library-globals/` and `text-parameters/hero-objectives/`): each trigger, outlined into the tool's input and written as a new trigger, renders the Editor's section, Ids aside. Not written yet: a Kept trigger's rewrite before it is converted (`convert_triggers` first), a file path literal (the renderer doesn't write one), and a comment an older Editor filed under a call with no blocks (thanson01's Wave Over AI Retreat, a Wait).

**Read back.** `outline_trigger` (`src/map/outline-trigger.ts`, #1034) reads one of a Mission's triggers back as the tool's input, Kept or the Blueprint's own, by its name or element Id. A Kept one is read into a Blueprint element as `convert_triggers` reads it, against the reach the tool reads, so a trigger outlines the same before and after it is converted. A Blueprint trigger's outline, given to `write_blueprint_trigger` unchanged, writes its file back byte for byte; `convert_triggers` and the tool write a trigger's file the same way (`blueprintTriggerFile`, the element in the schema's order). `outline_kept_trigger` stays the tuning outline, with each Param's Id for `tune_kept_triggers`. `outlineForAuthoring` (`src/triggers/authoring-outline.ts`) does the reading: functions by name where the name settles on them, parameters by name, blocks by slot name, locals by name, and lists what the input can't express. Every other part is read in the plainest form the tool writes the same where it stands, Ids aside: a preset value by its name (`"Operator": "=="`, `"Unit": "Any Unit"`, `{ "preset": "GasOff" }` where the parameter takes any value), a set of bits by its values' names (`{ "bits": ["Ignore Placement"] }`), a global or a member by its name (`{ "variable": "Hero Unit", "member": { "variable": "Artanis" } }`, with `library` where globals of two libraries have that name), a trigger and a local's type by name (`"Unit Group"`), and a literal as a number, `true`/`false` or its text (`"Type": "PalletGas"`). The tool says which: it builds each form it is offered quietly and tells the outline the first that comes out the same (`plainer`). A part whose name settles on another element, or on none, stays by its reference (two Kept globals named HyperionFighterGroup leave `{ "variable": "863AD0ED" }`). `authoringRoundTrip` writes that outline back through the tool as a rewrite of the trigger and compares the two, parameters in any order and a block's statements slot by slot (as Galaxy writes them). The coverage script's conversion column runs it over every converted trigger (`written back by the tool`): of the corpus's 264 converted triggers, 263 come back as they are.

**The library-wide test.** `tests/triggers/library-round-trip.test.ts` (#1035) writes a call to every function in `data/trigger-libraries.json` through the tool, from placeholder arguments: each parameter with no default given a plain literal of its type (`0`, `false`, a word, a preset type's first value), else the value of the plainest function giving its type, else a local, else a literal of its type; an event among the events, a condition among the conditions, an action among the actions, and a function's value set to a local (Set Variable), given to the plainest action taking its type, or compared (Comparison). Each trigger's outline writes its file back byte for byte (`blueprintTriggerFile`), and the engine writes its Galaxy. What can't be is listed by reason in `tests/triggers/library-refusals.json`; a refusal not on the list fails the test, and so does one listed that no longer happens (`UPDATE_REFUSALS=1` rewrites it). Of the game's 3,211 functions, 2,963 pass. A default that is a call leaving out a parameter (Sine's Facing Angle Of Unit with no Unit; Order With No Target with no Ability Command), as the library holds it, is copied as it stands, and its rewrite is refused (the outline reads the parameter left out as unset); the test gives such a parameter the call filled in, and lists the 32 functions with such a default apart (`defaultsLeavingOut`), with what the tool does with them as the library holds them.

## Element Ids

An element is known by its type and its Id together, never its Id alone. The Editor 5.0.17 saves we have looked at (the `editor-triggers` fixtures among them) give every element an Id no other element has, but an older Editor numbered each type apart: Blizzard's Liberty map `thanson01` has `<Element Type="Trigger" Id="00000029">`, `<Element Type="Variable" Id="00000029">` and `<Element Type="FunctionCall" Id="00000029">`, and 17 such shared Ids in all. A reference names its element's type (`<Variable Type="Variable" Id="00000029"/>`, `<Action Type="FunctionCall" Id="00000029"/>`), so the Triggers reader (`triggers-file.ts`), the splice (`splice-triggers.ts`) and the mod library reader (`libraryElements` in `library-xml.ts`) look each one up by both. A mod library does it too: Swarm Story Util's `E859A89C` is a FunctionCall in a trigger and the FunctionDef ZSS_PlayStoryModeEntryScenes, whose own calls share Ids with Params elsewhere. An item filed in Root or a folder is known the same way: the splice, the Editor-change check and a mod library's filing in its categories hold items by type and Id, and they take the previous compile's items from the compile record by each entry's kind and Id (`trigger:00000029` is the Trigger, `variable:00000029` the Variable). So a compile that converts thanson01's Trigger `00000029` replaces it and leaves the Variable filed where it was. A new element, a tuned copy's or a Compiled one, takes an Id no element of any type has, as the current Editor would; a converted library function keeps the Ids it was imported with, shared ones too. The one exception is a Compiled element that replaces the package's element of the same type and Id, such as a converted Kept item: the old save already shared that Id. The fixtures `packages/core/tests/fixtures/editor-triggers/shared-ids` and `library-shared-ids` are cut from thanson01 and Swarm Story Util.

## Game functions from their templates

Every call to a function the game's library data (`packages/core/data/trigger-libraries.json`) defines is written from that data by the template engine the mod generator uses (`library-galaxy.ts`), in the Kept renderer (`kept-trigger-galaxy.ts`) and the mission compile's map script writer (`write-map-script.ts`) alike ([ADR-0025](../adr/0025-typed-primitives-are-the-authoring-layer.md)): a ScriptCode template filled in (If Then Else, Pick Each, Switch, Action Queue, Or, Repeat), a native call by its identifier, an operator by its operands, any other as `libNtve_gf_<identifier>(…)`. Core's catalog entries name their calls; they don't write them, but for VCMI's two, which the data doesn't hold yet (#951). A Plugin's primitive with a `galaxy` of its own is written by it. The engine takes a scope: in a map, the map's own elements carry no `Library` and are named `gt_`, `gf_`, `gv_`, `lv_` and `lp_`, and an event's first argument is the trigger's variable (`TriggerAddEventUnitStartedAttack(gt_PlayerIsInCombat, null)`). The values and the calls in a template's slots go back to the writer that handed the call over. An event's unit is a reference to the unit (`UnitRefFromVariable(…)`) where its native takes a `unitref`, which is every event but Unit Enters Range Of Unit, whose other unit is a plain `unit` (`natives.galaxy`; a current Mission save writes `TriggerAddEventUnitRange(gt_…, null, UnitFromId(…), 8.0, true)`). A block whose condition slot is empty, and a call held in a slot its template doesn't write, are refused. A preset value the catalog lacks comes from the data too. A library's variable the map doesn't hold is typed, for a Switch on it, by the one plain type of its cases' values.

Forms checked against thanson01 (the fixture `packages/core/tests/fixtures/editor-triggers/template-fallback`):

- **An int or fixed literal given to an `#INITAUTOVAR`** (Repeat's count, For Each Integer's end and step; the saves hold no other type's) is the variable's constant initializer, declared with it, and the template sets nothing: `const int autoC6444FA3_n = 30;`, then `for (autoC6444FA3_i = 1; autoC6444FA3_i <= autoC6444FA3_n; …)`. A variable or a call given there is set where the template stands, as before. The current Editor writes it so (58 such `const int` declarations in the Editor 5.0.17 Mission saves we measured with), and so does thanson01's; an older Editor's, one that writes no `// Automatic Variable Declarations` line (Nova's and Campaign Common's libraries), declares it plain and sets it (`auto374950CA_n = 3;`), which isn't written.
- **A repeated value joined by an operator** (`#PARAM(val," " #PARAM(op) " ")`, the Arithmetic and And/Or Multiples) is the values with the operator between them, in parentheses: `(libChal_gv_cHLC_VICTORYPANELWAVEPANEL_Y + libChal_gv_cHLC_VICTORYPANELSCORE_HEIGHT + 80)` in the game's challenges mod, `((…) || (…))` in Liberty's tstory01.
- **A unit an event takes** is a reference: `UnitRefFromVariable("gv_x")` for a variable's, `UnitRefFromUnit(UnitFromId(n))` for a placed unit, `null` for any. No save shows a call's or a parameter's unit given to a trigger's event, so those are refused.
- **A template macro in a form the engine doesn't match** (Pick Each Player (Deprecated)'s `#SUBFUNCS(actions);`, which no save shows) is refused, as is a call held in a slot its template doesn't write, rather than written as text or dropped.
- **An older Editor's set of bits with none set** is `<ValueType Type="preset"/>` alone, naming no preset type; the parameter's own type in the data names it, and it is `0`.
- **A blank line between a trigger's conditions**, and none after the last, before the `if (testConds)` block's closing brace. thanson01's triggers with more than one condition have it (49 of them, with two to five conditions), and so does a current Mission save (every one of its 26 triggers with more than one condition written in its script; a 27th is disabled, and the Editor writes no Galaxy for it; the fixture `mod-library-calls`'s Enter Reactor Room). The renderer and the mission compile's map script writer (`write-map-script.ts`) both write it, with one helper in `write-map-script.ts`, tested against the fixture `packages/core/tests/fixtures/editor-triggers/three-conditions`, thanson01's "Add Convoy Marine into Unit Group". A comment or a disabled condition is written as nothing, so the live conditions either side of it have one blank line between them: the fixture `comment-condition`, Legacy of the Void's ptaldarim01's "Wave Shadow FX", checks a comment; a disabled condition is seen only by eye, in Liberty's ttosh03a ("TIP - Nuke Ready First Q", two disabled between live ones), whose actions call the campaign's libraries and so can't be rendered in a test. A Compiled trigger written before #971 has no blank lines; the next compile writes them. Tuning accepts a Kept trigger saved without them (by an earlier tune, or a compile before #971) as otherwise the Editor's, and its tuned section is written with them.

## Arrays and indexed values

What the Editor writes for an array variable and a value taken from one, in a library's `Triggers` (Nova, Swarm Story Util, Campaign Common) and a map's (thanson01), and what we write (#944):

- **An indexed value** is the Param's `<Variable/>`, then its `<StructMember/>` if it names a member, then one `<Array Type="Param"/>` per dimension indexed, each a Param of its own holding any value. The Editor writes the member's Param first, then the index values', each with what it holds: the order the library writer writes them.
- **Galaxy indexes the variable before it names a member**: `lib281DEC45_gv_zSS_Characters[lib281DEC45_gf_ZSS_CharacterIndex(lp_character)].lv_unit`. A member that is an array is indexed the same way, by the `<Array>` in the member's Param: `libNCMI_gv_nM_StealthAIDefendRegionArray[lv_i].lv_defendingUnitArray[lv_j].lv_unit`. Each dimension is its own brackets, in order: `libNCUI_gv_nU_EquipmentList[lp_equipmentSlot][lp_itemSlot]`.
- **A value given to a template** is written as any other value: thanson01's Repeat over `gv_unloadAmount[gv_escortIndex]` sets `auto37AAE177_n = gv_unloadAmount[gv_escortIndex];` where the template stands, since it isn't a literal.
- **An array variable's declaration** carries its sizes (the row above). Its initial value is the element's: the saves give an array local only a value Galaxy starts it with (`null`, `0`), and the Editor writes no initialization for it.

Not written: an array local with an initial value of its own (no save shows its Galaxy, the loop the Editor writes for a global's being in `InitVariables`), an event's unit taken from an array (no save shows its `UnitRefFromVariable` text), a size of a variable in another library (its Galaxy name isn't in reach), and `<ArrayIndex>` or `<ExpressionCode>` beside an index (a form of its own). Each is refused, naming it. Globals aren't written in Galaxy, a library's being in its header and a map's written by the compile, which writes no arrays. Checked against the fixtures `packages/core/tests/fixtures/editor-triggers/arrays` (Swarm Story Util's and Nova's libraries) and `indexed-values` (thanson01).

## Text values

A text given as a value is a `Param` holding only `<ValueType Type="text"/>`: its words aren't in `Triggers` but in GameStrings, keyed by the Param, `Param/Value/<id>` in a map and `Param/Value/lib_<library>_<id>` in a library. The Editor writes it as `StringExternal("<key>")`, or as `StringToText("")` when the text is empty, and an empty text's key either holds nothing (`Param/Value/1EAE5176=`) or is absent: a current Mission save has both, for the descriptions of two objectives it creates side by side, each written `StringToText("")` (the fixture `text-parameters/hero-objectives`). So whether a key holds any words decides it, not whether the key is there. The template engine (`textGalaxy` in `library-galaxy.ts`) and the Kept renderer write it so, from the keys that hold text (`textValueKeys`, every locale's GameStrings, a byte order mark allowed for); the mission compile's map script writer from its own value's text, as before. A mod library's function holding a text reads and writes back as the Editor saved it, its words carried in the interface's `strings` (`mod-strings.md`). Checked against Nova's `Format Time (Campaign)` (the fixture `text-parameters/mods/missionpacks/novacampaign.sc2mod`, an older Editor's save).

A package whose GameStrings is missing (a copy of Blizzard's maps may hold only TriggerStrings) leaves which texts are empty unknown: the coverage report then takes each to hold text.

## Expressions

The Editor's Arithmetic and Expression values are a `Param` holding `<ExpressionType Type="…"/>` (int, fixed, string or text), its text (`<ExpressionText>`) with `~<code>~` slots, and an `<ExpressionParam>` for each slot: a `Param` of its own holding the slot's value, then `<ExpressionCode Value="<code>"/>` last. The slots are listed in the Editor's order, not the text's (`~AttachPoint~ … ~X~,~Y~,~Z~ … ~Operation~` lists AttachPoint, Operation, Z, X, Y), and a code may stand twice in the text. Every Editor save in the game's data has that shape, the code last in each slot and no slot itself an expression. What the Editor writes, from its saves:

| Type | Galaxy | Example |
|---|---|---|
| int, fixed | the text in parentheses, as it stands, each slot its value | `~A~+(~B~-~A~)*~X~/~Y~` is `(ColorGetComponent(…)+(ColorGetComponent(…)-ColorGetComponent(…))*(lp_progress - lp_minValue)/(lp_maxValue - lp_minValue))` |
| string | the text's runs between slots as string literals, as they stand (`Cutscenes\\` stays two backslashes), joined to the slots' values by ` + `, in parentheses; an empty run is left out | `~Prefix~~Planet Name~` is `("CC_L_" + (lp_planet))`; a text with no slot, `("CarrierIcon")` |
| text | its words are in GameStrings, keyed `Param/Expression/<id>` in a map and `Param/Expression/lib_<library>_<id>` in a library, so it has no `ExpressionText`. Each slot its words name is set by a `TextExpressionSetToken("<key>", "<code>", <value>);` line before the statement it is in, in the Editor's order, and its value is `TextExpressionAssemble("<key>")` | `TextExpressionSetToken("Param/Expression/lib_ComC_6F77848E", "A", StringToText((lp_objective)));` |

A text expression's slot its words don't name gets no line: Void Prologue's Create Objective (Campaign) has two slots and the words `~A~`, and only A is set. One with no slots is `TextExpressionAssemble` alone (Heart of the Swarm's zspace01). The template engine (`expressionGalaxy` and `textExpressionGalaxy` in `library-galaxy.ts`) and the Kept renderer write them so, a text expression's words from GameStrings (`textValueKeys`); a mod library's function holding one reads and writes back as the Editor saved it, a text expression's words carried in the interface's `strings` (`mod-strings.md`).

Not written, each refused, naming it: a text expression whose words aren't known or are empty, or name a code no slot has; one outside a statement (a local's initial value) or given to a block itself (an If's condition, a loop's bound), or in another text expression's slot, as no save shows where its lines go; a string expression's text holding a quote or a line break; a slot the text doesn't name, or a code no slot has, in an int, fixed or string expression. An expression may be an `#INITAUTOVAR`'s value, set as a call's is (`auto<id>_ae = (CatalogFieldValueCount(…)-1);`). Checked against the fixtures `expressions/mods` (Campaign Common's and Nova's libraries, older Editor's saves, and Void Prologue's, a current one's) and `expressions/salvage-objective` (a current Editor's Mission save).

## Bodies with nothing to write

- **A function with no actions** has no `// Implementation` line: its body ends with its header, `// Automatic Variable Declarations` then `}`, or after its variables' initialization and their blank line. One whose actions are all comments or disabled has the line, with nothing after it. Void Prologue's PP_ResetTech (none) and PP_StoreTechBonusAtMissionBeginning (a comment), a current Editor's save; a Mission's Power Area - Move Units Away (none, with a local) and Play Mission Music (one disabled If Then Else). - **Bank Preload** (Ntve's `BankPreload`) writes no statement: the Editor lists the bank it names in the package's `BankList.xml` instead, which our compiles don't write or check: a package keeps the Editor's. Void Prologue's Load Campaign Data (a current Editor's save), Challenges' Load Challenge Data (the fixture's), Legacy of the Void's pulnar02. ## An older Editor's forms

The game's older libraries (Nova's, Campaign Common's, Swarm Story Util's, Challenges') were saved by an Editor that writes no `// Automatic Variable Declarations` line, and differ from the current Editor's in more than that line. None is written: the generator writes the current Editor's form, which the Editor reads and writes back as its own. The coverage report (`packages/core/scripts/trigger-coverage.mjs`, `asCurrentEditor`) takes such a save to the current forms before comparing, and counts a function that matches only then apart:

- the automatic variables declared first in the body, under no header, with a blank line after them (in a thread's trigger function, after the parameters it takes back);
- an `#INITAUTOVAR` given an int or fixed literal declared plain and set where its template stands (`auto374950CA_n = 3;`), not `const` with its value;
- For Each Integer's test for a negative step written `<= 0`, the template's `< 0`;
- Pick Each Unit In Unit Group counting up from 1 (`autoX_u = 1; for ( ; autoX_u <= UnitGroupCount(…) ; autoX_u += BoolToInt(…) )` and `UnitGroupUnit`), not down from the end with `UnitGroupUnitFromEnd` (Swarm Story Util's Story Show/Hide All Units);
- an If Then Else with no else actions written `else {` `}`, where the current Editor writes a blank line (seen in Swarm Story Util's and Challenges' libraries). A Switch's empty default is `else {` `}` in both.

With them allowed for and the rules above, every function the generator writes in the coverage report's corpus matches its Editor's Galaxy (#952).

## Calls into a dependency mod's library

A Mission's Kept triggers call its Campaign Mod's library functions as they call the game's: the libraries in reach of a map are the game's data and the library of each Workspace mod its DocumentInfo depends on, and the ones those mods depend on (`library-reach.ts`). Each mod's library is read from its Mod Blueprint's library interface, and any function the interface doesn't declare, from the mod package's Triggers and strings, its interface only. A call is written as the Editor writes it: by the function's own template where it has one (a library's own If Then), else `lib<id>_gf_<identifier>(…)`, the identifier from the function's name where it has no Identifier (`Sound Channel Volume - Speech` is `libCmpn_gf_SoundChannelVolumeSpeech()`), its parameters in the definition's order; a native one by its identifier. A conversation line given as a value is its id quoted: `"Story03|Line04047"`. The library's variables are still named by `bindLibraryNames` from the Editor's own Galaxy.

A Mission compile writes its triggers' calls into the Campaign Mod's library the same way, from the libraries in reach of the map its Blueprint's dependencies make (#974). A call into the Campaign Mod's library from a map that doesn't load the mod is refused, saying to add it: `it calls Bel1/0000B001, but the map doesn't load the Campaign Mod Bell-Story, whose library Bel1 is: add file:Mods\Bell-Story.SC2Mod to the Blueprint's dependencies`. A library event and a UI Component's function are still written by their own call (ADR-0025).

Not written: a call to an inline function (the Editor writes a value's body in the caller, and the interface gives none; no save in the game's data shows an inline action, so it is refused too), a disabled function (the Editor writes no Galaxy for it, and the Mod Blueprint's disabling stands over the package's copy), a call into a mod library whose package can't be read or whose id another mod's library has (refused with why; a mod's copy of a game library leaves the game's in reach), a preset value with no value of its own (a generated constant, whose name the interface doesn't give), and a mod's set of bits with none set (the interface doesn't say a preset type is bits). Checked against a Mission save, the fixture `packages/core/tests/fixtures/editor-triggers/mod-library-calls`.

A mod's library functions reach the libraries of the mods it depends on in the same way, for `convert-library` and `compile-mod` (`dependencyReach`): the dependencies are its Mod Blueprint's (its DocumentInfo's). A mod in a Workspace finds them among the Workspace's mods only: a Workspace has no extracted copy of the game's mods. A mod outside one is one of the game's own: each `file:` dependency is found by its path under the game's data, the folder holding the `Mods` or `Campaigns` folder the mod sits under (Nova's `file:Mods\missionpacks/campaigncommon.sc2mod`), matched in any case, and every library in its Triggers is in reach, with the mods that one depends on. A preset type is read for its base type and its values only, whatever else it holds. A function of a dependency's library that can't be read is refused by name and why, as a Kept function of the mod's own is: `it calls ComC/79A9ED48, whose definition can't be read: …`. A call into a library that isn't in reach names the mod dependencies that weren't found: `…, which no library in reach defines; it depends on campaigncommon, which isn't among the game's mods` (in a Workspace: `isn't one of the Workspace's mods (the game's own mods aren't read from a Workspace)`), as does one of a preset value, preset type or preset element. The game's mods that hold no library of their own aren't named: Core, Liberty, Swarm, Void, their Multi mods and Nova's art mod have no Triggers in the game's data (Core's Ntve and Swarm's Hots are the game's libraries). Each is named once, whatever case its dependencies spell it in. Under the game's data, a dependency's DocumentInfo and Triggers are found in any case. A game library's id (Ntve, Hots) in a dependency's Triggers stays the game data's, and a packed dependency (a file, not a folder) isn't read. A campaign's own standard libraries (`SwarmStory.SC2Campaign`'s SwaC, in `TriggerLibs/*.SC2Lib`) aren't read. Checked against Nova's save, the fixture `packages/core/tests/fixtures/editor-triggers/dependency-libraries`.

# Reference

Background on how the StarCraft II game client loads and runs maps. Most of it comes from [`sc2-arcade-watcher/sc2-ida-mcp-setup`](https://github.com/sc2-arcade-watcher/sc2-ida-mcp-setup), reverse-engineering notes on the Windows client (build 96921, 5.0.15). We run the Mac client, 5.0.17 (build 98310). File formats, cvar names, error strings and protobuf messages carry over; internal addresses don't. Each doc marks what has actually been seen on the Mac.

Our own Editor-verified findings, in [map-package-findings.md](./map-package-findings.md) and [editor-and-engine.md](./editor-and-engine.md), take precedence wherever these docs disagree with them.

Blizzard's cinematic sets available to cutscenes, from their `.SC2Cutscene` files, are catalogued in [`packages/core/data/cinematic-sets/README.md`](../../packages/core/data/cinematic-sets/README.md), regenerated with `npm run catalog-sets`. A Workspace's own sets, from its Campaign's files, are catalogued in its `cinematic-sets/` folder (`catalog-sets --private`). `npm run import-set` (or the MCP `import_set` tool) brings one into a Mission as a Set, `missions/<id>/sets/<set id>.json`, or into a mod with `--mod`, `mods/<id>/sets/<set id>.json`.

MapInfo, the other format taken from the same source, is documented in [map-package-findings.md](./map-package-findings.md#map-packages) and `packages/core/src/terrain/write-map-info.ts`.

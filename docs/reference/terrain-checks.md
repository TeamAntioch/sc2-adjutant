# Terrain format checks

Seven facts about the terrain files, from another project's notes (see `related-repos.md`, issue #745, part of #735). Each was checked against our writers and against Editor-saved maps on disk, read 2026-11-18. Nothing of that project's code or text is used, and its Surface Toolkit files were not opened. The facts were unverified here; this file records what the evidence says.

Evidence maps (Editor-saved): four Mission maps the Editor saved, `cliffs-and-doodads`, Ziggurat, Ephemeron LE and five melee fixtures. Each scan read `t3Terrain.xml`, `t3HeightMap`, `t3SyncCliffLevel` and `t3SyncHeightMap` straight off the unpacked `.SC2Map`. The committed Editor fixtures (`packages/core/tests/fixtures/editor-terrain/`) hold the xml, height map and sync cliff files but no sync height map.

| Fact | Outcome | Evidence |
|---|---|---|
| Ramp `dir`: 0 S, 1 N, 2 W, 3 E, 4-7 diagonal | Match | Our `RampDirection` is the same (`ramps.ts`), and the Editor wrote `dir` 0 and 2 for ramps placed climbing south and west (2026-10-25, `terrain-file-formats.md`). The diagonals: every Editor `<ramp dir>` 4, 5, 6, 7 on Ephemeron LE and one of the Mission maps carries the uphill vector of south-west, south-east, north-west, north-east on its `base` piece, which is what `rampXml` writes. Test: `format-facts.test.ts` ("ramp directions"). |
| Cliff rule for three-high and saddle cells | Match for the cliff mesh; **mismatch fixed** for the sync cliff level of a saddle | Mesh: every cliff cell whose four corners aren't all one level has `f` bit 1 in the Editor's maps, three-high and saddle included (970 three-high and 12 saddle on one Mission map, 1,461 and 12 on a second, 1,253 and 2 on Ephemeron LE; no flat cell has it), and `hasCliffMesh` says the same. Sync level (`syncCellLevels`): of 6,013 three-high terrain cells 6,001 take the high level, of 6,134 three-low 6,122 take the low level (the majority rule, as before; the odd ones are round the terrain object and ramps). Of 12,846 edge-split cells 12,806 take the low level. All 50 saddle cells (one level on one diagonal, another on the other) take the **high** level, on three maps (those two Mission maps and Ephemeron LE); we wrote the low. A generated map has them where a cliff cell's corners are a saddle, such as `RecipeSample`. Fixed in `cliffs.ts`, tests in `cliffs.test.ts`. |
| Sync-height level label | Match | The label is our `t3SyncCliffLevel` file (64 per level, in-between on ramps) and the level channel of `t3SyncHeightMap`. The map's level per vertex equals `r2` at every vertex of the Editor's maps (`terrain-file-formats.md`). The vertex level is the corner rule's, unchanged by the saddle fix. |
| Uneven ramp rails cause black seams | Not seen in one Editor test (2026-11-21); ours are even | The seam is a rendering effect, and no Editor map or fixture here has an uneven ramp. What we can show is that we never write one: a straight ramp's heights depend on the distance from the lane's centre only, and the wide and narrow diagonal templates are mirror-symmetric about the lane in both heights and sync cells. Test: `format-facts.test.ts` ("ramp rails"). Editor test, 2026-11-21 (the author, three screenshots, Editor version not recorded): on a generated ramp map, with the height brush used beside a ramp, no black seam was seen along the ramp from above or at an angle. One ramp, one brush, and how uneven the rail became was not measured, so this does not show an uneven ramp is safe: a seam may need a larger step or a particular ramp. |
| `cliffCellList num = w·h/4` | Match | `num` is `(w/2)·(h/2)` in all 22 maps scanned (Editor-saved and ours), including the non-square 160×168 and 208×160, and in our output at 128, 256, 208×160 and 96. Test: `format-facts.test.ts` ("list sizes"). |
| `blockTextureSetList num = w·h/64` | Match | The same 22 maps, `(w/8)·(h/8)`. Same test. |
| SMAP102 Q12 scale 4096 non-zero | Match | Bytes 28-39 of `t3SyncHeightMap` are three int32 of 4096 in every map scanned that has the file (19, Editor-saved and ours), and our writer writes the same. Test: `format-facts.test.ts` ("t3SyncHeightMap header"). Whether the game refuses 0 is untested: we never write it. |

## Left for an Editor check

- Whether an uneven ramp rail draws a black seam: one test showed none (2026-11-21). A larger step between the rails, and a diagonal ramp, were not tried.
- Whether the saddle fix changes anything in game: the sync cliff level feeds pathing and cliff-level checks, and the Editor writes the high level, so after the fix our files agree with it. A Test Document on a map with a saddle cliff (one corner pair up on a diagonal) would show it.

## Output changes

The saddle fix changes a generated map wherever a saddle cell exists: `t3SyncCliffLevel` there, and what the compile derives from the cell levels (the base heights, `t3SyncHeightMap`, `t3SyncTextureInfo`, `t3TextureMasks` and the minimap). In the golden test only one Mission's full compile has one; its hero run is unchanged. Its `golden.json` was regenerated in its own layer.
